# Excel Consolidation & Validation Automation

Turns a folder of monthly Excel exports into **one clean, validated, formatted report**, with duplicates and data errors flagged for review instead of silently passed through.

> All sample data is **fully synthetic** (generated by `generate_sample_data.py`; every customer name begins with "Sample"). No real client or employer data is used.

## The problem
Many businesses rebuild the same report every month by hand: opening several spreadsheets, copying rows into a master file, removing duplicates, fixing IDs that lost their leading zeros, and hoping nothing was missed. It's slow, it's error-prone, and nobody can see which rows were changed or dropped.

## The solution in plain English
Drop the monthly files into one folder and run one command. The script reads every file, checks it against clear rules, and builds a single report. Clean rows go into the report. Anything wrong (a bad date, a duplicate, a missing column) is listed on its own sheet with the exact file and row, so a person can fix it. The original files are never changed.

## What this demo shows (and doesn't claim)
- **Shows:** reliable consolidation, validation, duplicate detection, ID preservation and a traceable, formatted report on realistic but synthetic data.
- **Does not claim:** time savings or results for any real business. Actual benefit depends on each client's files and process.

## What this automation does
| Step | Result |
|---|---|
| Reads every `.xlsx` in a folder | Handles 5–10+ monthly files in one run |
| Normalises headers | `" Unit Price "`, `UNIT PRICE` and `unit_price` are treated as the same column |
| Validates structure | Files missing a required column are rejected and reported |
| Validates values | Dates, whole-number quantities, non-negative prices, invoice ID format, required fields |
| Preserves identifiers | IDs are read as text: `000123` and postcode `0800` stay intact |
| Repairs lost zeros | IDs Excel stored as numbers (`123`) are restored to `000123` and logged as warnings |
| Detects duplicates | Exact re-exports and *conflicting* records (same invoice, different values) |
| Produces a formatted report | Summary, Consolidated, Duplicates and Exceptions sheets |
| Reports statistics | Files, rows read, rows excluded, duplicates, warnings, revenue, run time |
| Never touches source files | Inputs are read-only; output inside the input folder is refused |

## Output: `sample_output/consolidated_report.xlsx`
- **Summary**: processing statistics, revenue by month, revenue by product.
- **Consolidated**: clean, de-duplicated rows with `source_file` and `source_row` for traceability.
- **Duplicates**: each removed row, its type, and where the original was first seen.
- **Exceptions**: every error and warning with file, Excel row, column, issue and original value.

Sample run (7 synthetic files):
```
Files found                    7
Files processed                6
Files rejected                 1
Rows read                      243
Rows with errors (excluded)    5
Duplicate rows removed         3
Rows in final report           235
Warnings                       41
```

## How duplicates are handled
- Duplicates are matched on `invoice_id`.
- **Exact duplicate** (all values identical): the extra copy is removed and listed on the Duplicates sheet.
- **Conflicting duplicate** (same invoice, different values): the **first occurrence by filename order is kept**. The later row is removed, listed on the Duplicates sheet, and logged as a warning on the Exceptions sheet for a person to decide. The script does not guess which version is correct.

## Installation (Windows)
Requires Python 3.10+. Tested on Windows 11 with Python 3.15, pandas 3.1 and openpyxl 3.1.
```powershell
cd excel-consolidation-demo
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```
macOS/Linux: use `source .venv/bin/activate`.

## Usage
```powershell
# 1. (Optional) regenerate the synthetic sample files
python generate_sample_data.py

# 2. Consolidate
python consolidate.py --input sample_data/input --output sample_output

# 3. Run tests
python -m pytest -q
```
To use your own files, point `--input` at a folder of `.xlsx` files with these columns (header case and spacing don't matter):
`invoice_id, invoice_date, customer_id, customer_name, postcode, product_code, quantity, unit_price`

## Deliberate issues in the sample data
| File | Issue | Handling |
|---|---|---|
| `sales_2026-02.xlsx` | 2 rows re-exported from January | Removed as exact duplicates |
| `sales_2026-03.xlsx` | Customer IDs saved as numbers | Zeros restored, 40 warnings |
| `sales_2026-04.xlsx` | Invalid date, text quantity, blank name, negative price, bad invoice ID | 5 rows excluded, reported |
| `sales_2026-05.xlsx` | Messy headers, `dd/mm/yyyy` text dates, conflicting duplicate | Normalised; conflict flagged |
| `sales_2026-06.xlsx` | `quantity` column missing | Whole file rejected, reported |

## Tests
11 pytest tests cover leading-zero preservation, ID repair, exact and conflicting duplicates, rejected files, invalid values, messy headers, input immutability, output-folder safety, synthetic-data check and an end-to-end run.

## Limitations
- Schema is fixed in code (`REQUIRED_COLUMNS`); a new layout needs a small config change.
- Reads the **first sheet** of each workbook only; `.xls`/`.csv` are not read.
- Files are processed in **filename order**, so a conflicting duplicate keeps the earlier file's row, even if the later one is the correction. Use sortable names (e.g. `sales_2026-01.xlsx`) and review the Exceptions sheet.
- Zero-padding assumes fixed-width IDs (6-digit customer, 4-digit postcode); each repair is logged for review.
- Dates accepted: real Excel dates, `yyyy-mm-dd`, `dd/mm/yyyy` (Australian format). US `mm/dd/yyyy` isn't supported.
- Extra columns are ignored. Rows are loaded into memory, which is fine for tens of thousands of rows but not millions.
- The report file is overwritten on each run (source files never are).
